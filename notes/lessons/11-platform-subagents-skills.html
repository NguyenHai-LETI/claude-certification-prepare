Hình dung đời thường
Học lái xe có ba giai đoạn. Trước hết là làm quen vô lăng, côn, phanh (các bộ phận cơ bản). Sau đó là đường đi nhiều làn, trạm xăng, bãi đỗ (hạ tầng để chạy lâu dài). Cuối cùng là đồng hồ, biển báo, giới hạn tốc độ (kiểm soát). Claude Platform có đúng ba lớp như vậy, và 13 bài của khóa đi lần lượt từ lớp thấp lên cao.

2.1 What is the Claude Platform? (Bài 1)

Claude Platform = REST API + SDK + CLI + Console. Ba lớp:

  • Primitives: Messages API, tool use, files, web search, code execution, MCP, skills — những gì bạn gọi trực tiếp trong code.
  • Infrastructure: managed agents, retries, queues, observability, prompt caching, memory — cơ sở hạ tầng để scale lên production.
  • Controls: dashboards, evaluations, workspaces, spend limits, request logs — điều hành hệ thống thực tế.

Shorthand: "build with primitives, scale on infrastructure, run with control."

Ví dụ đầu tiên của khóa dùng đúng lớp Primitives: một lời gọi Messages API để soạn nháp trả lời ticket hỗ trợ.

import anthropic
client = anthropic.Anthropic()

response = client.messages.create(
    model="claude-haiku-4-5",
    max_tokens=1024,
    system=TONE_AND_GUIDELINES,
    messages=[{"role": "user", "content": ticket_content}],
)
draft = "".join(block.text for block in response.content if block.type == "text")
  • model: chọn model. Ở đây là Haiku vì việc soạn nháp đơn giản.
  • system: lời dặn cố định về giọng văn và quy định, áp dụng cho cả cuộc hội thoại.
  • messages: nội dung ticket của khách, với role là user.
  • Dòng cuối ghép mọi khối text trong response.content thành bản nháp (xem 2.2 vì sao phải lặp qua các khối).
Dùng Haiku cho tác vụ đơn giản như draft reply; Sonnet cho production thông thường; Opus cho reasoning phức tạp.

2.2 Your First API Call (Bài 2)

Hình dung đời thường
Gọi API giống gửi một phiếu yêu cầu vào quầy. Phiếu ghi rõ: nhờ ai làm (model), được viết tối đa bao nhiêu (max_tokens), và nội dung nhờ (messages). Quầy trả về một xấp giấy, mỗi tờ một loại: tờ văn bản, tờ yêu cầu dùng công cụ… Bạn phải lật từng tờ xem là loại gì, không thể coi cả xấp là một tờ.

Mỗi request dùng messages.create với model, max_tokens, và messages. Response content là array of blocks, không phải plain string — phải loop qua và kiểm tra block.type.

import Anthropic from "@anthropic-ai/sdk";
const client = new Anthropic();

const response = await client.messages.create({
  model: "claude-sonnet-5",
  max_tokens: 2048,
  system: "You are a terse senior code reviewer. Give feedback in one paragraph.",
  messages: [{ role: "user", content: `Review this code:\n${buggyCode}` }],
});

for (const block of response.content) {
  if (block.type === "text") console.log(block.text);
}
  • system đặt vai: người review code ngắn gọn, một đoạn.
  • Vòng for đi qua từng khối. Chỉ khối có type === "text" mới in ra.
Sai
  • Coi response.content là một chuỗi và in thẳng
  • Viết key vào source: api_key = "sk-..."
Đúng
  • Lặp qua các khối, kiểm tra block.type rồi mới đọc block.text
  • Để key trong .env.local và đọc từ biến môi trường
Bảo mật: Lưu API key trong .env.local, không hardcode vào source code.
Thuật ngữ
max_tokens
Giới hạn độ dài câu trả lời. Token là đơn vị chữ mà model đếm, tạm hiểu là một mẩu từ.
block
Một khối trong content, có type như text hoặc tool_use.
.env.local
File cấu hình cục bộ chứa bí mật, không đưa vào git.

2.3 Choosing the Right Model (Bài 3)

Hình dung đời thường
Cần chuyển một thùng đồ lặt vặt, bạn đi xe máy chứ không thuê xe tải. Chuyển cả nhà thì mới thuê xe tải. Chọn model cũng vậy: việc nhỏ dùng model nhỏ, rẻ và nhanh; việc nặng mới dùng model lớn.

Bốn tier model (từ mạnh nhất): Fable (thử thách cực khó) → Opus (reasoning sâu, phân tích phức tạp) → Sonnet (cân bằng tốc độ/chi phí, phù hợp production) → Haiku (nhanh và rẻ nhất, phân loại/routing/extraction).

Quy tắc: thử Haiku trước, nếu chất lượng không đủ mới lên Sonnet, chỉ dùng Opus khi thực sự cần. Dùng response.usage theo dõi input/output tokens.

models = ["claude-haiku-4-5", "claude-sonnet-5", "claude-opus-5-5"]
for model in models:
    response = client.messages.create(model=model, max_tokens=300,
        messages=[{"role": "user", "content": prompt}])
    print(model, response.usage)  # input_tokens, output_tokens

Đoạn code chạy cùng một prompt qua ba model rồi in số token. Bạn so câu trả lời và so chi phí để chọn model rẻ nhất vẫn đủ tốt.

Cost routing: Haiku phân loại tệp → Sonnet soạn bản cập nhật → Opus chỉ cho RFP phức tạp.
Thuật ngữ
Tier
Một bậc model trong họ Claude.
Cost routing
Chia việc theo độ khó: việc dễ cho model rẻ, việc khó mới cho model đắt.
response.usage
Số token vào và ra của lần gọi, dùng để tính tiền.

2.4 The Agent Loop Explained (Bài 4)

Hình dung đời thường
Một nhân viên được giao “tìm thời tiết rồi gợi ý trang phục”. Anh ấy xin tra thời tiết, nhận kết quả, rồi tự quyết là đã đủ để trả lời hay cần tra thêm. Không ai đứng giữa để nhắc từng bước. Agent là như vậy: Claude tự đi tiếp cho tới khi thấy xong.

Agent = Claude tự chạy cả hai phía hội thoại, không cần người ở giữa. Vòng lặp:

  1. Gửi message + tools → Claude trả về hoặc final answer hoặc tool_use
  2. Nếu stop_reason == "tool_use": chạy tool, gửi tool_result lại
  3. Nếu stop_reason == "end_turn": kết thúc
  4. Trường hợp khác (max_tokens, refusal): dừng lại, không loop tiếp
tools = [{"name": "get_weather", "description": "Get the current weather for a city.",
    "input_schema": {"type": "object", "properties": {
        "city": {"type": "string", "description": "The city to get weather for"}},
        "required": ["city"]}}]

messages = [{"role": "user", "content": "What should I wear in Austin today?"}]
while True:
    response = client.messages.create(model="claude-sonnet-5",
        max_tokens=1024, tools=tools, messages=messages)
    if response.stop_reason == "end_turn":
        for block in response.content:
            if block.type == "text": print(block.text)
        break
    elif response.stop_reason == "tool_use":
        tool_results = []
        for block in response.content:
            if block.type == "tool_use":
                result = run_tool(block.name, block.input)
                tool_results.append({"type": "tool_result",
                    "tool_use_id": block.id, "content": result})
        messages.append({"role": "assistant", "content": response.content})
        messages.append({"role": "user", "content": tool_results})
    else:
        print(f"Stopped early: {response.stop_reason}")
        break

Chạy thử với câu hỏi “What should I wear in Austin today?”

VòngClaude trả vềstop_reasonCode làm gì

2Văn bản gợi ý trang phục dựa trên kết quả đóend_turnIn câu trả lời, break

  • Nhánh else bắt mọi lý do dừng khác (max_tokens, refusal) và thoát ngay, không lặp tiếp.
Sai

Đúng
  • Có đủ ba nhánh: end_turn, tool_use và nhánh dừng cho giá trị khác
  • Nối cả lượt assistant và tool_result (kèm tool_use_id) trước khi gọi lại
Cốt lõi. Claude kiểm soát reasoning; bạn kiểm soát loop và tools. Nhánh “trường hợp khác” là chỗ vòng lặp phải biết dừng.

2.5 Tool Use, Thinking, Built-in Tools (Bài 5–7)

Hình dung đời thường
Tool giống dụng cụ trong hộp đồ nghề kèm nhãn dán. Thợ chọn dụng cụ dựa vào nhãn, nên nhãn mơ hồ thì chọn nhầm. Thinking giống việc thợ nháp trên giấy trước khi làm. Built-in tool giống dụng cụ thuê sẵn ở cửa hàng (server tool) hoặc dụng cụ cửa hàng bán kèm hướng dẫn nhưng bạn tự cầm (client tool).

Tool use: định nghĩa tool bằng JSON schema (name + description + input_schema). Description phải cụ thể — đây là nguyên nhân số 1 khiến agent chọn sai tool. Tool Runner (beta) tự xử lý toàn bộ vòng lặp.

Extended thinking (Bài 6): Trên Opus 5, thinking bật tự động (adaptive). Dùng output_config={"effort": "high"} để kiểm soát độ sâu (low/medium/high/xhigh/max). Hiển thị summary với thinking={"type": "adaptive", "display": "summarized"}.

response = client.messages.create(
    model="claude-opus-5",
    max_tokens=16000,
    thinking={"type": "adaptive", "display": "summarized"},
    output_config={"effort": "high"},
    tools=[weather_tool],
    messages=[{"role": "user", "content": "Plan a road trip..."}]
)
  • thinking kiểu adaptive: model tự quyết có cần nghĩ sâu không. display: "summarized" cho bạn xem bản tóm tắt phần suy nghĩ.
  • effort là nút chỉnh độ sâu, từ low đến max. Chọn high cho việc cần cân nhắc kỹ như lên kế hoạch chuyến đi.

Built-in tools (Bài 7): Server tools (web_search, code_execution, web_fetch) chạy trên infrastructure của Anthropic — không cần agent loop, kết quả trả về trong cùng response với block type server_tool_use. Client tools (memory, bash) chạy ở code bạn, Anthropic đã có schema sẵn.

Thuật ngữ

Cách mô tả kiểu dữ liệu đầu vào của tool: tên field, kiểu, field nào bắt buộc.

Bẫy. Description tool mơ hồ là nguyên nhân số 1 khiến agent chọn sai tool. Và đừng viết agent loop cho server tool, vì kết quả đã nằm trong cùng response.

2.6 Skills, MCP, Context Management, Managed Agents (Bài 8–13)

Hình dung đời thường
Bạn thuê một trợ lý. Skill là cuốn sổ quy trình trợ lý mở khi gặp đúng loại việc. MCP là ổ cắm chuẩn để nối trợ lý với các dịch vụ bên ngoài như Slack hay Linear. Context management là cách giữ bàn làm việc gọn khi hồ sơ chất cao. Managed agents là thuê luôn văn phòng có sẵn: Anthropic lo chỗ ngồi và vòng làm việc, bạn chỉ giao việc.

Skills (Bài 8): SKILL.md chứa hướng dẫn thực thi ("how" Claude làm việc, không phải "what"). Upload bằng client.skills.create(), attach qua container.skills cùng code execution tool. Chỉ load name+description ban đầu, full content load on demand.

MCP (Bài 9): Dùng cho third-party services (Linear, Slack...). Khai báo mcp_servers + tools với type: "mcp_toolset". Có thể lọc tool bằng default_config: {enabled: false} rồi enable từng tool cụ thể. Beta header: betas=["mcp-client-2025-11-20"].

response = client.beta.messages.create(
    model="claude-opus-5", max_tokens=1024,
    mcp_servers=[{"type": "url", "url": "https://mcp.linear.app/mcp",
        "name": "linear", "authorization_token": os.environ["LINEAR_MCP_TOKEN"]}],
    tools=[{"type": "mcp_toolset", "mcp_server_name": "linear"}],
    betas=["mcp-client-2025-11-20"],
    messages=[{"role": "user", "content": "What tools do you have available?"}]
)
  • mcp_servers khai báo máy chủ MCP: địa chỉ, tên, token. Token lấy từ biến môi trường, không viết vào code.
  • tools với mcp_toolset bật bộ tool của máy chủ đó cho Claude dùng.
  • betas bật tính năng beta. Vì vậy gọi qua client.beta.messages.

Managed Agents (Bài 11–12): Anthropic host vòng lặp agent. Bốn primitive: Agent (model + system prompt + toolset) → Environment (sandbox + networking) → Session (một lần chạy) → Events (stream các message). Mở stream trước khi gửi kickoff message.

agent = client.beta.agents.create(name="Line Counter", model="claude-opus-5",
    system="You are a helpful agent that completes small file tasks.",
    tools=[{"type": "agent_toolset_20260401", "default_config": {"enabled": True}}])
environment = client.beta.environments.create(name="env",
    config={"type": "cloud", "networking": {"type": "limited"}})
session = client.beta.sessions.create(agent=agent.id, environment_id=environment.id)

with client.beta.sessions.events.stream(session_id=session.id) as stream:
    client.beta.sessions.events.send(session_id=session.id, events=[{
        "type": "user.message",
        "content": [{"type": "text", "text": "Create a file, count its lines, report back."}]}])
    for event in stream:
        if event.type == "agent.message":
            for block in event.content:
                if block.type == "text": print(block.text, end="")
        elif event.type == "session.status_idle":
            break

Đọc code theo thứ tự: tạo agent, tạo environment (networking kiểu limited để hạn chế ra mạng), tạo session từ hai ID đó, mở stream, gửi user.message trong khối with, rồi lặp qua event cho tới session.status_idle.

Có thể gộp hai bước (tạo session, gửi event đầu) thành một lệnh bằng initial_events. Nguồn: platform.claude.com, Start a session.
Sai

Kickoff message
Tin nhắn đầu tiên giao việc cho session.
Cốt lõi. Bốn pattern context: load khi cần, tóm tắt, cache phần ổn định, ghi nhớ qua session. Với managed agents, nhớ chuỗi Agent → Environment → Session → Events.

3. Introduction to Subagents — 4 bài

CCAR-F D1 CCDV-F D1

Hình dung đời thường
Bạn nhờ một đồng nghiệp “đọc giúp 30 file rồi báo lại chỗ nào xử lý đăng nhập”. Đồng nghiệp lật hết 30 file, bạn không phải xem từng file. Bạn nhận một đoạn tóm tắt và bàn làm việc của bạn vẫn gọn. Subagent làm đúng như vậy.

3.1 What Are Subagents? (Bài 1)

Subagent chạy trong context window riêng. Toàn bộ intermediate work (file reads, searches, tool calls) không ảnh hưởng context chính. Chỉ có summary trả về. Claude Code lưu full transcript của subagent ra file riêng. Ba built-in subagents: General purpose, Explore (đọc/tìm codebase), Plan (phân tích trước khi plan mode).

Thuật ngữ
Context window
“Bàn làm việc” của model: lượng nội dung nó nhìn thấy cùng lúc.
Intermediate work
Công việc trung gian như đọc file, tìm kiếm, gọi tool.
Transcript
Bản ghi đầy đủ những gì subagent đã làm.
General purpose · Explore · Plan
Ba subagent có sẵn: đa dụng, đọc và tìm codebase, phân tích trước khi plan mode.

3.2 Creating a Subagent (Bài 2)

File markdown với YAML frontmatter tại .claude/agents/ (project scope) hoặc ~/.claude/agents/ (user scope). Các field:

---
name: code-quality-reviewer
description: Use this agent when you need to review recently written or modified code for quality, security, and best practice compliance.
tools: Bash, Glob, Grep, Read, WebFetch, WebSearch
model: sonnet   # haiku | sonnet | opus | fable | inherit
color: purple
---
  • name: tên định danh subagent.
  • description: khi nào nên dùng. Claude đọc dòng này để quyết định có giao việc hay không.
  • tools: các tool subagent được dùng.
  • model: model riêng cho subagent. inherit nghĩa là dùng model của agent chính.
  • color: màu hiển thị trong giao diện.

Body dưới frontmatter là system prompt. Thêm "proactively" vào description để Claude tự động delegate không cần hỏi. Restart Claude Code nếu folder agents/ mới tạo trong session hiện tại.

Thực tế 11/2026 Từ Claude Code v2.1.63, tool tạo subagent được đổi tên từ Task thành Agent (issue #29677). Tài liệu thi vẫn dùng tên Task; biết ý nghĩa là đủ.

3.3 Designing Effective Subagents (Bài 3)

Hình dung đời thường
Nhờ một người “kiểm tra giúp” mà không nói kiểm tra gì và báo lại thế nào thì kết quả sẽ lan man. Đưa họ một mẫu phiếu có sẵn các mục thì họ biết điền xong là hết việc.

Bốn yếu tố quan trọng:

  1. Description cụ thể: description quyết định cả khi nào delegate lẫn nội dung task được giao. Nếu description yêu cầu main agent cung cấp danh sách file cụ thể, main agent sẽ truyền thông tin đó.
  2. Output format rõ ràng: đây là thay đổi quan trọng nhất. Định nghĩa format trong system prompt tạo "điểm dừng tự nhiên" — subagent biết khi nào xong. Ví dụ: Summary / Critical Issues / Major Issues / Minor Issues / Recommendations / Approval Status.
  3. Báo cáo obstacles: thêm section "Obstacles Encountered" để main thread không phải tự phát hiện lại workaround.
  4. Giới hạn tool: research subagent chỉ cần Glob/Grep/Read; code reviewer cần Bash nhưng không cần Edit/Write.
Sai
  • Description chung chung: “Reviews code”
  • Không quy định định dạng đầu ra, subagent không biết khi nào dừng
  • Cho research subagent đủ mọi tool, kể cả Edit và Write
Đúng
  • Description nêu rõ khi nào dùng và cần main agent đưa gì (ví dụ danh sách file)
  • Định nghĩa các mục: Summary, Critical Issues, Major Issues, Minor Issues, Recommendations, Approval Status, kèm Obstacles Encountered
  • Research chỉ có Glob, Grep, Read; reviewer có Bash nhưng không có Edit, Write
Cốt lõi. Output format là thay đổi có tác dụng lớn nhất: nó cho subagent một điểm dừng tự nhiên.

3.4 Using Subagents Effectively (Bài 4)

Câu hỏi quyết định: "Intermediate work có quan trọng với main thread không?"

Dùng subagentKHÔNG dùng subagent
Research/exploration (chỉ cần kết quả)Pipeline tuần tự (mỗi bước phụ thuộc bước trước)
Code review (cần fresh perspective)Test runner (cần xem full output để debug)
Task cần custom system prompt khácExpert persona ("Python expert") — không thêm giá trị
Bẫy. Dùng subagent cho test runner làm mất output đầy đủ mà bạn cần để debug, vì main thread chỉ nhận summary. Tạo subagent chỉ để đóng vai “Python expert” cũng không thêm giá trị.

4. Introduction to Agent Skills — 6 bài

CCAR-F D3 CCDV-F D3

Hình dung đời thường
Thư viện có hàng nghìn cuốn, nhưng thủ thư chỉ đọc nhãn trên gáy sách khi bạn bước vào. Chỉ khi bạn hỏi về nấu ăn, thủ thư mới rút cuốn sách nấu ăn ra và mở nội dung. Skill cũng vậy: Claude chỉ nạp tên và mô tả, nội dung đầy đủ nạp khi việc khớp.

4.1–4.2 What Are Skills + Creating Your First Skill

Skill = thư mục chứa SKILL.md + (tùy chọn) scripts, references, assets. File SKILL.md có frontmatter (name + description) và phần hướng dẫn bên dưới. Claude chỉ load name+description lúc khởi động; full content chỉ load khi match request.

Vị tríPhạm viUse case
~/.claude/skills/Personal — toàn bộ projectsCommit style, code explanation style cá nhân
.claude/skills/Project — chia sẻ qua gitPR checklist, brand guidelines của team
Enterprise managed settingsOrg-wide, ưu tiên cao nhấtCompliance workflows bắt buộc

Ưu tiên name conflict: Enterprise > Personal > Project. Plugin skills được namespace (/plugin-name:skill-name) nên không xung đột.

Thực tế 11/2026 Academy ghi rõ hơn: trong Claude Code mọi field frontmatter đều tùy chọn và chỉ description được khuyến nghị; name mặc định là tên thư mục. Khi upload lên Claude.ai hoặc Claude API thì name (chữ thường, số, gạch ngang, tối đa 64 ký tự) và description (tối đa 1.024 ký tự) là bắt buộc. Nguồn: Academy, Configuration and multi-file skills.
Thuật ngữ
Frontmatter
Khối YAML ở đầu file, giữa hai dòng ---, chứa thông tin mô tả file.
Progressive disclosure
Nạp thông tin theo tầng: nhãn trước, nội dung khi cần, chi tiết sau cùng.
Scope
Phạm vi áp dụng của skill: cá nhân, dự án hay toàn tổ chức.
Namespace
Tiền tố tên (như /plugin-name:skill-name) để hai skill khác nguồn không trùng nhau.

Viết name và description cho đúng

Lúc khởi động Claude chỉ thấy name và description của mọi skill, nên hai trường này quyết định skill có được dùng đúng lúc không.

PhầnQuy tắcVí dụ

Luôn luôn, Không bao giờÍt và cụ thể; quá nhiều quy tắc tuyệt đối làm skill cứng nhắc"Never send the report; produce a draft only."

Bẫy. Skill không bao giờ được gọi thường do description chỉ nói "làm gì" mà không nói "khi nào". Sửa description trước khi nghĩ tới việc chuyển nội dung sang CLAUDE.md.

4.3 Configuration and Multi-File Skills

Frontmatter fields:

---
name: codebase-onboarding
description: Helps new developers understand how the system works.
allowed-tools: Read, Grep, Glob, Bash   # pre-approve (không giới hạn tool)
model: sonnet
---

allowed-tools: pre-approve các tool trong scope của skill (clear khi user gửi message tiếp theo). disallowed-tools: chặn tool cụ thể. Progressive disclosure: giữ SKILL.md dưới 500 dòng, đặt nội dung chi tiết vào references/. Scripts trong skill chạy mà không load nội dung vào context — chỉ output được tính token.

Sai
  • Nghĩ allowed-tools giới hạn Claude chỉ dùng các tool đó
  • Nhồi mọi thứ vào một SKILL.md hàng nghìn dòng
  • Bảo Claude “đọc” script lớn vào context
Đúng
  • allowed-tools chỉ pre-approve; muốn chặn dùng disallowed-tools
  • SKILL.md dưới 500 dòng, chi tiết để ở references/
  • Cho Claude chạy script: chỉ output tốn token
Thực tế 11/2026 Academy nhấn mạnh allowed-tools chỉ pre-approve, không hạn chế Claude dùng tool khác; quyền cho các tool còn lại vẫn theo thiết lập thường. Ghi Bash đơn lẻ là pre-approve lệnh shell nói chung, nên chỉ dùng với skill đáng tin hoặc thu hẹp theo mẫu, ví dụ Bash(git status *). Nguồn: Academy, Configuration and multi-file skills.

4.4 Skills vs Other Claude Code Features

Hình dung đời thường
Trong công ty: nội quy ai cũng phải theo mỗi ngày (CLAUDE.md). Sổ tay nghiệp vụ mở khi gặp đúng việc (skill). Cổng từ chặn tự động, không phụ thuộc ai nhớ (hook). Phòng ban riêng nhận việc và báo lại (subagent). Đối tác bên ngoài nối qua hợp đồng chuẩn (MCP).
FeatureKhi nào dùng
CLAUDE.mdAlways-on conventions (TypeScript strict mode, naming rules)
SkillsTask-specific expertise, load on demand khi match request
HooksEvent-driven (trước/sau tool call), enforcement thực sự
SubagentsIsolated context, delegated work với tool access riêng
MCP serversExternal tools và integrations từ third-party
Bẫy. Quy tắc luôn đúng thì để CLAUDE.md, đừng viết thành skill (skill chỉ nạp khi khớp). Việc phải được ép chặt thì dùng hook, vì lời dặn trong skill không phải enforcement.

4.5–4.6 Sharing Skills + Troubleshooting

Chia sẻ: commit vào .claude/skills → tự động qua git. Plugin → marketplace. Enterprise managed settings → /etc/claude-code/.claude/skills/ trên Linux. Subagent custom có thể preload skill qua field skills: trong frontmatter agent file.

Troubleshoot (theo thứ tự):

Triệu chứngHành động
Skill không triggerCải thiện description, thêm trigger phrases thực tế
Skill không loadKiểm tra path/tên file (SKILL.md), dùng claude --debug
Sai skill được dùngLàm description rõ ràng và khác biệt hơn
Skill bị overrideKiểm tra priority hierarchy, đổi tên skill

Validate trước khi share: claude plugin validate ~/.claude/skills hoặc claude plugin validate .claude/skills (cần Claude Code v2.1.233+).

Thuật ngữ
Trigger
Việc Claude quyết định dùng skill vì yêu cầu khớp description.
Preload
Nạp sẵn skill cho subagent ngay từ đầu, qua field skills:.
Plugin và marketplace
Gói đóng sẵn để cài và chia sẻ, đăng ở một “chợ” plugin.
Cốt lõi. Description là thứ quyết định skill có chạy không. Hầu hết lỗi “skill không chạy” sửa bằng việc viết description rõ và có cụm từ người dùng thật sự gõ.
