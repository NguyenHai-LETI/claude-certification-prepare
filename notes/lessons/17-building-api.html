2. Module 1: Accessing Claude with the API — Bài 1–8

CCDV-F D2 CCDV-F D5 Trùng với Bài 01 §Cấu trúc request, đọc lướt

Hình dung đời thường
Bạn ngồi nhà hàng và gọi món qua phục vụ. Phục vụ (server của bạn) cầm thẻ thành viên (API key) vào bếp, đưa phiếu gọi món (request) cho đầu bếp (Claude). Đầu bếp làm xong thì phục vụ mang món ra. Điểm lạ: đầu bếp quên sạch mọi thứ sau mỗi phiếu. Muốn đầu bếp nhớ bạn đã gọi gì, bạn phải đưa lại cả tờ phiếu cũ mỗi lần. Đó là multi-turn.
Thuật ngữ
Request / response
Request là gói dữ liệu bạn gửi đi (model, max_tokens, messages). Response là gói Claude trả về (nội dung, usage, stop_reason).
Token
Mẩu văn bản nhỏ (một từ hoặc một phần từ) mà model đọc và tính tiền theo đó.
content block
Một khối trong content của message. Có thể là text, tool_use, thinking…
stop_reason
Lý do Claude dừng: max_tokens, end_turn, stop_sequence, hoặc tool_use.
Streaming
Nhận câu trả lời từng mẩu ngay khi được tạo, thay vì đợi cả câu.
Prefill
Viết sẵn phần đầu của câu trả lời Claude (một message assistant) để Claude viết tiếp.

2.1 Luồng request (Bài 1 — Accessing the API)

Client app → Server của bạn → Anthropic API → Claude → Response → Server → Client. API key phải ở server, không bao giờ đặt ở client-side code. Claude xử lý input qua: tokenization → embedding → contextualization → generation (sampling từ probability distribution).

Response chứa: generated message, usage (input/output tokens), stop_reason. Stop khi: max_tokens đạt, end_turn tự nhiên, hoặc stop_sequence gặp.

Sai
  • Nhúng ANTHROPIC_API_KEY vào JavaScript chạy trên trình duyệt
  • Commit file .env lên Git
Đúng
  • Client gọi server của bạn, server gọi Anthropic
  • Key nằm trong .env hoặc secret store, .env nằm trong .gitignore

2.2 API key và setup (Bài 2–3)

Tạo key tại Claude Console → Billing → API keys. Copy ngay, chỉ hiện 1 lần. Lưu vào .env:

ANTHROPIC_API_KEY="sk-ant-..."
from dotenv import load_dotenv
load_dotenv()
from anthropic import Anthropic

client = Anthropic()
model = "claude-haiku-4-5"

message = client.messages.create(
    model=model,
    max_tokens=1000,
    messages=[{"role": "user", "content": "What is quantum computing? Answer in one sentence"}]
)
message.content[0].text   # truy cập text từ content block
max_tokens là ceiling, không phải target. Claude dừng tự nhiên trước nếu đã xong. Lỗi phổ biến: đặt quá thấp → response bị cắt giữa chừng.

2.3 Multi-turn conversations (Bài 4)

Claude không lưu conversation history — toàn bộ do bạn quản lý. Mỗi request phải gửi lại toàn bộ lịch sử:

messages = []

def add_user_message(messages, content):
    messages.append({"role": "user", "content": content})

def add_assistant_message(messages, content):
    messages.append({"role": "assistant", "content": content})

def chat(messages, system=None):
    params = {"model": model, "max_tokens": 1000, "messages": messages}
    if system:
        params["system"] = system
    return client.messages.create(**params).content[0].text

# Multi-turn example
add_user_message(messages, "Define quantum computing in one sentence")
reply = chat(messages)
add_assistant_message(messages, reply)
add_user_message(messages, "Write another sentence")
chat(messages)  # Claude biết "another sentence" về quantum computing
Sai
  • Chỉ gửi câu hỏi mới: Claude không biết “another sentence” nói về gì
  • Quên add_assistant_message sau mỗi câu trả lời
Đúng
  • Lưu danh sách messages ở phía bạn
  • Thêm câu trả lời của Claude trước khi thêm câu hỏi kế

2.4 System prompts (Bài 5)

System prompt định hướng tone, vai trò, behavior. Truyền qua parameter system (không accept system=None):

TUTOR_PROMPT = """You are a math tutor. Give hints before full solutions.
Walk students through problems step by step.
Do NOT give direct answers or tell them to use a calculator."""

reply = chat(messages, system=TUTOR_PROMPT)
# Claude sẽ hỏi câu hỏi dẫn dắt thay vì đưa đáp án ngay

2.5 Temperature (Bài 6)

Temperature 0–1 reshapes probability distribution của token prediction:

RangeBehaviorUse case
0.0–0.3Predictable, consistentFactual Q&A, coding, data extraction, moderation
0.4–0.7BalancedSummarization, education, constrained creative writing
0.8–1.0Varied, creativeBrainstorming, marketing copy, joke generation
Claude 4.6+ không nhận temperature. Claude Haiku 4.5 (và anthropic<1) vẫn hỗ trợ. Trên model mới, dùng prompt thay thế.
Thực tế 11/2026 Tài liệu hiện hành của Anthropic ghi temperature, top_p, top_k không được hỗ trợ từ Claude 4.7 trở lên: đặt giá trị khác mặc định trả lỗi 400, và từ API version 2026-10-21 mọi giá trị đều lỗi. Bài học nói mốc 4.6+; với đề thi, cứ nhớ “model mới không nhận temperature”. Nguồn: tài liệu Messages API.

2.6 Response streaming (Bài 7)

Streaming gửi từng chunk ngay khi Claude tạo ra — cải thiện perceived responsiveness đáng kể (Claude có thể mất 10–30 giây để generate đầy đủ):

# Simplified text streaming (cách phổ biến nhất)
with client.messages.stream(
    model=model, max_tokens=1000,
    messages=[{"role": "user", "content": "Tell me a story"}]
) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)  # hiển thị ngay từng chunk

# Lấy full message sau stream (để lưu DB)
final_message = stream.get_final_message()

Event types: message_start → content_block_start → content_block_delta (text chunks) → content_block_stop → message_stop. Forward text chunks lên client ngay, lưu final message cho storage.

2.7 Structured data (Bài 8)

Prefill assistant message + stop sequence để lấy JSON thuần không có markdown wrapper. Chỉ dùng với Claude Haiku 4.5 (cũ) — Claude 4.6+ dùng tool_use để force structured output.

# Prefill + stop sequence (Claude Haiku 4.5 / anthropic<1 only)
messages = [
    {"role": "user", "content": "List 3 fruits as JSON array"},
    {"role": "assistant", "content": "```json\n"}  # prefill kích hoạt JSON mode
]
response = client.messages.create(
    model=model, max_tokens=500, messages=messages,
    stop_sequences=["```"]  # dừng trước closing fence
)
import json
json.loads(response.content[0].text.strip())

Cách mới cho model hiện hành: khai một tool có input_schema đúng hình dạng JSON bạn muốn, rồi ép Claude gọi nó bằng tool_choice. Dữ liệu nằm sẵn trong block.input, không cần cắt markdown (bài 04 đã dạy chi tiết tool_choice).

Bẫy. Schema đảm bảo hình dạng, không đảm bảo giá trị đúng. Vẫn phải kiểm tra nghiệp vụ (ngày hợp lệ, số trong khoảng cho phép) ở code của bạn.

3. Module 2: Prompt Evaluation — Bài 9–14

CCDV-F D4 Trùng với Bài 13 §Introduction to Evals — 4 bài, đọc lướt

Hình dung đời thường
Giáo viên soạn đề cương mới và muốn biết nó có tốt không. Cách kém: cho một học sinh làm thử rồi tin ngay kết quả. Cách tốt: cho cả lớp làm cùng một bộ đề, chấm điểm từng bài, tính điểm trung bình, sửa đề cương rồi cho làm lại và so điểm. Prompt evaluation làm đúng như vậy với prompt: “lớp học” là dataset, “người chấm” là grader.
Thuật ngữ
Eval (evaluation)
Quy trình đo chất lượng prompt bằng một bộ test case và một cách chấm điểm.
Dataset
Bộ test case (3–100 ca) dùng để chạy lại mỗi khi sửa prompt.
Producer
Lần gọi Claude tạo ra output cần chấm.
Grader
Thứ chấm điểm output: một model khác (model-based) hoặc code (code-based).

3.1 Tại sao cần eval (Bài 9)

Ba lựa chọn sau khi viết prompt: (1) test 1 lần và ship — rủi ro cao; (2) test vài lần và patch corner case — vẫn miss nhiều edge case; (3) chạy eval pipeline với dataset + grader + iteration — tốn effort nhưng reliable nhất. Eval tìm điểm yếu trước production.

3.2 Eval workflow (Bài 10–12)

5 bước cơ bản: (1) Draft prompt; (2) Tạo eval dataset (3–100 test cases); (3) Feed từng case qua Claude; (4) Grade mỗi output (score 1–10); (5) Thay đổi prompt, chạy lại, so sánh score trung bình.

def run_prompt(test_case, prompt_template):
    messages = [{"role": "user", "content": prompt_template.format(**test_case)}]
    return chat(messages)

def run_test_case(test_case, prompt_template):
    output = run_prompt(test_case, prompt_template)
    score = grade(test_case, output)   # 1-10
    return {"output": output, "test_case": test_case, "score": score}

def run_eval(dataset, prompt_template):
    results = [run_test_case(tc, prompt_template) for tc in dataset]
    avg = sum(r["score"] for r in results) / len(results)
    return results, avg

# So sánh 2 prompt versions
_, score_v1 = run_eval(dataset, PROMPT_V1)   # e.g. 7.66
_, score_v2 = run_eval(dataset, PROMPT_V2)   # e.g. 8.70 → V2 tốt hơn
Sai
  • Thử prompt một lần, thấy ổn là ship
  • Vá từng corner case khi gặp, không đo lại
  • Đổi nhiều thứ cùng lúc rồi không biết cái nào có tác dụng
Đúng
  • Chạy cả dataset, có điểm số trước và sau
  • Thay đổi một thứ mỗi lần, đo lại
  • Giữ phiên bản prompt có điểm trung bình cao hơn
Cốt lõi. Eval biến “có vẻ tốt hơn” thành một con số so sánh được. Dùng Haiku làm grader (rẻ), Sonnet làm producer.

3.3 Model-based grading (Bài 13)

Grader = Claude model đánh giá output. Yêu cầu strengths + weaknesses + reasoning + score — thiếu reasoning thì scores tập trung quanh 6. Dùng Haiku cho grader (rẻ hơn), Sonnet cho producer:

def model_grader(task, output):
    response = chat([{"role": "user", "content": f"""
Evaluate this output for the task: {task}

Output: {output}

Provide:
1. Strengths
2. Weaknesses
3. Reasoning
4. Score (1-10): SCORE: X"""}], system="You are a strict quality evaluator.")
    # Parse score từ "SCORE: X"
    return int(response.split("SCORE:")[-1].strip().split()[0])

3.4 Code-based grading (Bài 14)

Kiểm tra syntax/format lập trình — nhanh và deterministic:

def grade_syntax(output, format_type):
    """Returns 10 (valid) or 0 (invalid)"""
    try:
        if format_type == "json": json.loads(output); return 10
        elif format_type == "python": ast.parse(output); return 10
        elif format_type == "regex": re.compile(output); return 10
    except: return 0

def combined_score(task, output, format_type):
    syntax = grade_syntax(output, format_type)
    quality = model_grader(task, output)
    return (syntax + quality) / 2  # điều chỉnh weights theo use case

4. Module 3: Prompt Engineering — Bài 15–19

CCDV-F D6 Trùng với Bài 06 §Cấu trúc prompt, đọc lướt

Hình dung đời thường
Bạn nhờ một bạn mới đi mua đồ. “Mua cho mình ít đồ ăn” khiến bạn ấy phải đoán. “Mua 6 quả trứng, 1 hộp sữa không đường, trước 5 giờ, cất trong ngăn mát” thì ai làm cũng ra kết quả giống nhau. Nếu còn nhờ việc khó diễn đạt, bạn đưa luôn một ví dụ mẫu. Prompt engineering là kỹ năng viết lời nhờ như thế cho Claude.
Thuật ngữ
Prompt
Toàn bộ chỉ dẫn và dữ liệu bạn đưa cho Claude trong một lần gọi.
Interpolate
Chèn giá trị biến (tên, số liệu) vào chỗ giữ chỗ trong prompt, ví dụ {height}.
One-shot / multi-shot
Đưa một / nhiều ví dụ mẫu vào prompt. Còn gọi là few-shot.
Sai
  • “Tell me about solar panels” (không nói rõ cần gì)
  • Dán dữ liệu lẫn với chỉ dẫn, Claude khó phân biệt
Đúng
  • “Write three paragraphs explaining how solar panels work” (động từ hành động, độ dài rõ)
  • Bọc dữ liệu trong thẻ XML như <athlete_information>

4.1 Iterative cycle (Bài 15)

Quy trình: (1) Set goal → (2) Write basic prompt → (3) Evaluate → (4) Apply techniques → (5) Re-evaluate → lặp lại. Thay đổi một thứ mỗi lần, đo impact, build on what works. Score thấp lần đầu (2.3/10) là bình thường.

4.2 Clear and direct + Specific (Bài 16–17)

Clarity: Dùng action verbs (Write/Create/Generate). Vague: "Tell me about solar panels" → Clear: "Write three paragraphs explaining how solar panels work."

Specificity — 2 loại guidelines:

  • Output quality guidelines: length, structure, required elements, tone. Thêm guidelines này vào gần như mọi prompt.
  • Process steps: ordered steps để Claude follow — dùng cho tasks phức tạp cần systematic reasoning.
Kết quả thực tế: Thêm guidelines nâng score từ 3.92 → 7.86 (hơn gấp đôi).

4.3 XML tags (Bài 18)

XML tags phân tách content rõ ràng khi prompt có nhiều components:

prompt = f"""Generate a one-day meal plan based on the athlete information below.

<athlete_information>
Height: {height}
Weight: {weight}
Goal: {goal}
Dietary restrictions: {restrictions}
</athlete_information>

Include: total daily calories, macronutrient breakdown, meals with specific foods."""
Dùng XML tags khi: input lớn, nhiều variables interpolated, cần phân biệt rõ instructions vs data.

4.4 Few-shot examples (Bài 19)

Examples (one-shot/multi-shot) dạy Claude pattern khó diễn đạt bằng instruction. Đặc biệt hữu ích cho edge cases và output format phức tạp:

prompt = f"""Classify the sentiment of this tweet.

<sample_input>Great, another Monday!</sample_input>
<ideal_output>Negative (sarcasm — context indicates frustration)</ideal_output>

<sample_input>{tweet}</sample_input>
Classify:"""

Best practices: Dùng XML tags để structure examples; giải thích tại sao example là "ideal"; lấy examples từ highest-scoring eval results; cover failure cases quan trọng nhất.

5. Module 4: Tool Use — Bài 20–31

CCDV-F D8 Trùng với Bài 18 §Tool Definition Anatomy (Bài 1–2), đọc lướt

Hình dung đời thường
Claude như một nhân viên giỏi nhưng ngồi trong phòng kín, không có mạng. Bạn đưa cho họ một danh sách điện thoại nội bộ (tool schema). Khi cần biết giờ hiện tại, họ viết giấy nhờ: “Hãy gọi số get_current_datetime” (tool_use). Bạn gọi giúp, ghi kết quả ra giấy (tool_result) và đưa lại. Họ đọc rồi trả lời. Claude không tự bấm máy, code của bạn mới chạy tool.
Thuật ngữ
Tool schema
Bản khai báo tool: name, description, input_schema (JSON Schema).
tool_use block
Khối Claude trả về để xin gọi tool: có id, name, input.
tool_result block
Khối bạn gửi lại kết quả: có tool_use_id (khớp với id trên), content, is_error.
Server tool

5.1 Giới thiệu tool use (Bài 20)

Tool use cho Claude quyền truy cập real-time data và external systems. Luồng 4 bước: (1) Gửi message + tool schemas; (2) Claude trả tool_use block; (3) Code của bạn execute tool; (4) Trả tool_result, nhận final answer từ Claude.

5.2 Tool functions và schemas (Bài 22–23)

Tool function = Python function thông thường. Tool schema = JSON schema mô tả function đó cho Claude:

def get_current_datetime(format: str = "%Y-%m-%d %H:%M:%S") -> str:
    """Get current date and time."""
    if not format: raise ValueError("format required")
    return datetime.now().strftime(format)

get_current_datetime_schema = {
    "name": "get_current_datetime",
    "description": "Returns current date/time. Use when user asks about today's date, current time, or needs to calculate relative dates. Returns formatted datetime string.",
    "input_schema": {
        "type": "object",
        "properties": {
            "format": {"type": "string",
                       "description": "strftime format string, e.g. '%Y-%m-%d' for date only, '%H:%M:%S' for time only"}
        },
        "required": ["format"]

}
Description tốt = tool use đúng. Nói rõ: khi nào dùng tool này, dữ liệu gì nó trả về, mô tả chi tiết từng parameter.

5.3 Message blocks và tool results (Bài 24–25)

messages = [{"role": "user", "content": "What time is it?"}]

    model=model, max_tokens=1000, messages=messages,

# Execute tool

# Trả tool result
messages.append({"role": "user", "content": [{
    "type": "tool_result",
    "tool_use_id": tool_block.id,     # phải khớp với id của tool_use block

    model=model, max_tokens=1000, messages=messages,

5.4 Multi-turn tool loop (Bài 26–28)

Vòng lặp xử lý nhiều tool calls liên tiếp:

def run_conversation(messages, tools):
    while True:
        response = client.messages.create(
            model=model, max_tokens=1000, messages=messages, tools=tools)
        messages.append({"role": "assistant", "content": response.content})

        if response.stop_reason == "end_turn":
            return response  # Claude xong, không cần tool nữa

        # Có tool_use blocks → execute và trả results
        tool_results = []
        for block in response.content:
            if block.type == "tool_use":
                result = run_tool(block.name, block.input)
                tool_results.append({
                    "type": "tool_result",
                    "tool_use_id": block.id,
                    "content": str(result)
                })
        messages.append({"role": "user", "content": tool_results})
Sai
  • Chỉ append phần text của response, bỏ tool_use block
  • tool_use_id không khớp, hoặc quên gửi tools ở lần gọi cuối
Đúng
  • Append nguyên response.content vào history
  • Mỗi tool_use có một tool_result cùng id, lỗi thì is_error: true

6.3 Embeddings và vector search (Bài 34–36)

Embedding = numerical representation of meaning (array of floats). Dùng VoyageAI (Anthropic không provide embedding API):

import voyageai
voyage_client = voyageai.Client()

def embed(text, model="voyage-3-large", input_type="query"):
    return voyage_client.embed([text], model=model, input_type=input_type).embeddings[0]

# Similarity: cosine similarity (1 = identical, 0 = unrelated, -1 = opposite)
# cosine_distance = 1 - cosine_similarity (0 = identical)

RAG flow: embed all chunks (input_type="document") → store in vector DB → embed query (input_type="query") → find nearest chunk → build prompt với retrieved chunk.

6.4 BM25 và multi-index pipeline (Bài 37–38)

BM25 (lexical search) complement cho semantic search — tìm exact terms (IDs, technical terms) mà embedding có thể miss:

store = BM25Index()
for chunk in chunks: store.add_document({"content": chunk})
results = store.search("INC-2023-Q4-011", 3)  # tìm exact ID

Reciprocal Rank Fusion (RRF) merge kết quả từ cả hai indexes theo rank position: score = Σ 1/(k + rank_i(doc)), k=60 thông thường. Chunk được cả 2 indexes rank cao → score tổng cao → retrieve đúng.

Cốt lõi. Embedding giỏi bắt nghĩa, BM25 giỏi bắt từ khóa chính xác như INC-2023-Q4-011. Dùng cả hai rồi gộp bằng RRF để không bỏ sót.

7.4 Prompt caching (Bài 43–45)

Cache preprocessing work của large static content — giảm 90% cost trên cached portion (read cache rẻ hơn 10x so với write). Default cache 5 min, 1-hour option available:

response = client.messages.create(
    model=model, max_tokens=1024,
    system=[{
        "type": "text",
        "text": LARGE_STATIC_SYSTEM_PROMPT,       # 10K+ tokens
        "cache_control": {"type": "ephemeral"}    # Cache this!
    }],
    tools=[*other_tools, {**last_tool, "cache_control": {"type": "ephemeral"}}],
    messages=[{"role": "user", "content": [{
        "type": "text", "text": large_document,
        "cache_control": {"type": "ephemeral"}    # Cache document
    }]},
    {"role": "user", "content": user_question}]   # Variable query
)
print(response.usage.cache_creation_input_tokens)  # > 0 lần đầu
print(response.usage.cache_read_input_tokens)       # > 0 các lần sau
Cache rules: (1) Processing order: tools → system → messages; (2) Max 4 breakpoints/request; (3) Min 4096 tokens cho Haiku 4.5; (4) Thay đổi 1 ký tự invalidates cache; (5) Phải dùng longhand text block format (không phải plain string) để đặt cache_control.
Sai

Đúng

8.2 Viết MCP server (Bài 50, 53)

FastMCP dùng decorators + type hints để auto-generate JSON schemas:

from mcp.server.fastmcp import FastMCP
from pydantic import Field

mcp = FastMCP("Document Server")
docs = {}

@mcp.tool()
def read_doc_contents(
    doc_id: str = Field(description="The document ID to read, e.g. 'report.pdf'")
) -> str:
    """Read contents of a document by ID."""
    if doc_id not in docs: raise ValueError(f"Document {doc_id} not found")
    return docs[doc_id]

@mcp.tool()
def edit_document(
    doc_id: str = Field(description="Document to edit"),
    old_text: str = Field(description="Text to find"),
    new_text: str = Field(description="Replacement text")
) -> str:
    """Edit a document with find-and-replace."""
    if doc_id not in docs: raise ValueError(f"Document {doc_id} not found")
    docs[doc_id] = docs[doc_id].replace(old_text, new_text)
    return "Done"
Dùng mcp[cli]<2 — version 2 đổi tên FastMCP → MCPServer.

@mcp.prompt()

Một dây chuyền nhà máy đi theo các công đoạn cố định, ai cũng biết bước kế tiếp: đó là workflow. Một người quản lý dự án được giao mục tiêu “mở chi nhánh mới”, tự quyết bước nào làm trước: đó là agent. Dây chuyền ổn định, dễ kiểm tra. Người quản lý linh hoạt nhưng khó đoán trước. Bài 03 đã dạy phân biệt này, ở đây xem cách dựng từng mẫu bằng code.
Thuật ngữ
Parallelization
Chạy nhiều lần gọi Claude cùng lúc, mỗi lần một khía cạnh, rồi gộp.
Chaining
Chia việc thành các bước nối tiếp, bước sau dùng đầu ra bước trước.
Routing
Phân loại đầu vào trước, rồi chuyển tới pipeline chuyên biệt.
Evaluator-optimizer
Producer tạo kết quả, grader chấm và góp ý, producer sửa. Lặp cho tới khi đạt.
Environment inspection
Agent quan sát kết quả hành động của mình (đọc file, chạy test, chụp màn hình) để biết có làm đúng không.

WorkflowAgent
Định nghĩaPredetermined steps, bạn control flowGoal + tools, Claude tự quyết định steps
Dùng khiBiết steps cụ thể, UX có giới hạnGoal rõ nhưng path không biết trước

Hướng dẫn thực tế: Dùng workflow khi có thể. Chuyển sang agent khi workflow không handle được variety of requests. Reliability > novelty — user care về product hoạt động ổn định.

10.2 Parallelization workflow (Bài 62)

Gửi cùng input đến nhiều Claude calls song song, mỗi call focus vào 1 aspect, aggregate kết quả:

import asyncio

async def evaluate_material(material_type, part_image, criteria):
    return await claude_async(f"Evaluate {material_type} for this part.\nCriteria: {criteria}\nImage: [image]")

async def material_selection(part_image):
    # Parallel calls — mỗi cái focus 1 loại vật liệu
    results = await asyncio.gather(
        evaluate_material("metal", part_image, METAL_CRITERIA),
        evaluate_material("polymer", part_image, POLYMER_CRITERIA),
        evaluate_material("ceramic", part_image, CERAMIC_CRITERIA)
    )
    # Aggregation
    return await claude_async(f"Compare these analyses and recommend:\n{results}")

10.3 Chaining workflow (Bài 63)

Phá task phức tạp thành sequential steps, mỗi step builds on previous. Hiệu quả khi single large prompt consistently miss một số constraints:

async def create_social_video(topic):
    # Step 1: Research
    research = await claude_async(f"Research '{topic}' for a short video")
    # Step 2: Script
    script = await claude_async(f"Write a short video script:\n{research}")
    # Step 3: Polish (focus only on fixing specific issues)
    return await claude_async(f"""Revise this script:
1. Remove AI-authorship references
2. Remove emojis
3. Replace cringey writing with professional prose

Script: {script}""")

10.4 Routing workflow (Bài 64)

Categorize input trước, rồi route đến specialized pipeline — mỗi pipeline được optimize cho loại đó:

CATEGORIES = ["Entertainment", "Educational", "Comedy", "Personal vlog", "Reviews", "Storytelling"]

async def create_video(topic):
    # Step 1: Route
    category = await claude_async(f"""
<topic>{topic}</topic>
<categories>{', '.join(CATEGORIES)}</categories>
Which category best fits this topic? Reply with just the category name.""")
    # Step 2: Specialized pipeline
    prompt_template = SPECIALIZED_PROMPTS[category.strip()]
    return await claude_async(prompt_template.format(topic=topic))
Dùng sai chỗ
  • Một prompt khổng lồ liệt kê mọi ràng buộc, Claude bỏ sót vài cái: nên dùng chaining
  • Gọi tuần tự các phân tích độc lập nhau, chậm không cần thiết: nên dùng parallelization
Dùng đúng chỗ
  • Chaining khi bước sau phụ thuộc bước trước
  • Parallelization khi các phần độc lập. Routing khi mỗi loại đầu vào cần cách xử lý khác nhau

10.5 Agent tools và environment inspection (Bài 65–66)

Abstract tools = combinable tools. Claude Code dùng generic tools (bash/read/write/edit) thay vì task-specific — Claude tự figure out cách combine chúng cho complex tasks.

Environment inspection: Claude cần feedback loop để biết actions có work không — tương tự screenshot trong computer use:

  • Read file trước khi edit (không break existing code)
  • Run tests sau implementation (verify thành công)
  • Check API responses (validate kết quả)
  • Screenshot sau UI interactions (xác nhận state)
Design rule: Với mỗi action trong agent, hỏi "How will Claude know if this worked?" Cung cấp tools để observe kết quả — Claude sẽ tự correct errors thay vì blind execution.

10.6 Evaluator-optimizer (nối lại với Module 2)

Mẫu này gắn producer và grader của Module 2 vào một vòng lặp ngay trong sản phẩm. Producer tạo kết quả, grader chấm và nêu điểm yếu, producer sửa theo góp ý. Lặp tới khi đạt ngưỡng hoặc hết số vòng tối đa (đặt giới hạn để không lặp vô hạn).

Cốt lõi. Evaluator-optimizer là workflow vì bạn quyết định vòng lặp và điều kiện dừng. Nó khác agent ở chỗ các bước không do Claude tự chọn.

11. Lưu ý ôn thi

Hình dung đời thường
Trước giờ thi, bạn không đọc lại cả giáo trình mà xem bản đồ ôn tập: domain nào nặng điểm, ý nào hay bị hỏi. Các khối dưới đây là bản đồ đó, theo thứ tự trọng số.
CCDV-F D2 (33,1%) — Applications and Integration: Đây là domain nặng nhất. Nắm chắc: messages.create parameters (model/max_tokens/messages), response structure (content blocks, stop_reason, usage), streaming event types, multi-turn history management, prompt caching (cache_control, breakpoints, minimum tokens, processing order tools→system→messages), Batch API (custom_id, polling, 50% discount), Files API (upload → file_id → reuse), code execution tool (Docker, no network). Web search tool (type string, max_uses, allowed_domains).
CCDV-F D5 (16,8%) — Model Selection: Model tiers (Fable/Opus/Sonnet/Haiku), temperature ranges và use cases, extended thinking (budget_tokens, min 1024, max_tokens constraint), usage.input_tokens/output_tokens. Cost routing pattern: Haiku classify → Sonnet draft → Opus complex only.
CCDV-F D6 (11%) — Prompt Engineering: Clear/direct (action verbs), specific (output quality guidelines + process steps), XML tags (khi nào cần), few-shot (edge cases, format examples, source từ eval results). Iterative eval cycle.
CCDV-F D8 (10,6%) — Tools and MCPs: Tool schema structure (name + description + input_schema), tool_use block (id/name/input), tool_result block (tool_use_id/content/is_error), multi-turn tool loop, fine-grained tool calling (eager_input_streaming), MCP architecture (3 capabilities: tools/resources/prompts, 2 transports: stdio/HTTP).
CCAR-F D1 (27%) — Agentic Architecture: Workflow = predetermined steps (you control). Agent = goal + tools (Claude controls). Parallelization (async gather, aggregate), chaining (sequential focus), routing (categorize → specialize), evaluator-optimizer (producer + grader + loop). Environment inspection = feedback loop cho agents.
CCAR-F D4 (20%) — Prompt Engineering & Structured Output: Structured output qua tool_use với tool_choice={"type": "tool", "name": "..."}, Pydantic model_json_schema(). Eval-driven prompt iteration. Chaining để handle complex multi-constraint prompts.
