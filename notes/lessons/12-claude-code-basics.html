1. Tổng quan

Hình dung đời thường
Bạn thuê một đồng nghiệp mới ngồi cạnh bàn. Người này đọc được mọi tài liệu trong phòng, mở được máy tính của bạn, tự chạy thử chương trình và báo kết quả. Nhưng trước mỗi việc quan trọng, như xoá file hay cài phần mềm, người đó hỏi bạn một câu: “Tôi làm việc này được không?”. Claude Code làm việc đúng như vậy với dự án phần mềm của bạn.

Khóa Claude Code 101 (12 bài) là tài nguyên nhập môn chính thức dành cho developer mới bắt đầu với Claude Code. Nội dung phủ toàn bộ CCAR-F D3 (20%) và CCDV-F D3 (3,1%).

Bạn chưa cần biết lập trình giỏi để theo bài này. Chỉ cần nắm bốn từ: terminal (cửa sổ gõ lệnh), IDE (phần mềm soạn code như VS Code), codebase (toàn bộ code của một dự án) và agent (AI tự làm nhiều bước thay vì chỉ trả lời một câu).

Thuật ngữ
Terminal
Cửa sổ nơi bạn gõ lệnh bằng chữ. Claude Code chạy ở đây hoặc trong IDE.
IDE
Phần mềm soạn và chạy code (VS Code, JetBrains). Claude Code có extension cho hai loại này.
Codebase
Toàn bộ file code của một dự án.
Agent
AI tự lặp nhiều bước (đọc, sửa, chạy) cho tới khi xong việc. Xem bài 07 về agent.

1.2 Các cách khởi động Claude Code

CLI (command-line interface) là chương trình bạn gọi bằng lệnh claude trong terminal. Một flag là phần đi kèm lệnh, bắt đầu bằng dấu gạch (-p, -c), để đổi cách chạy. Cùng một công cụ có hai kiểu dùng: tương tác (bạn và Claude nhắn qua lại) và không tương tác (chạy một lần rồi thoát, dùng trong script và CI).

LệnhLàm gìKiểu
claudeMở phiên tương tácTương tác
claude "explain this project"Mở phiên tương tác, kèm sẵn câu hỏi đầu tiênTương tác
claude -p "explain this function"Trả lời một lần rồi thoát (-p là print)Không tương tác
cat logs.txt | claude -p "explain"Đưa nội dung file vào qua pipe rồi hỏiKhông tương tác
claude -cTiếp hội thoại gần nhất trong thư mục hiện tạiTương tác
claude -r "auth-refactor"Mở lại một phiên theo ID hoặc tênTương tác
Bẫy. Phiên -p không có ai để hỏi quyền, nên mọi quyền phải khai sẵn trước (xem bài 13, mục 7). Còn gõ claude trơn luôn mở phiên mới với context trống; muốn tiếp hội thoại hôm qua thì phải chủ động dùng -c hoặc -r.

2. What Is Claude Code?

CCDV-F D3 Nền

Hình dung đời thường
Hỏi đường bằng tin nhắn khác với thuê tài xế. Chatbot AI thường giống người nhắn lại “rẽ trái, đi thẳng 500 m”, còn bạn tự lái. Claude Code giống tài xế: nhận điểm đến rồi tự lái, đổi làn, dừng đèn đỏ, và hỏi bạn khi cần qua đoạn đường lạ.

Claude Code là AI coding agent tích hợp trực tiếp vào terminal và IDE. Khác với AI coding assistants thông thường (chỉ suggest code), Claude Code hành động trong codebase của bạn: đọc file, chạy tests, commit code, tạo PR, toàn bộ từ một hội thoại.

Ba điểm khác biệt chính:

  • Context-aware (biết ngữ cảnh): đọc codebase của bạn, không chỉ dựa vào training data.
  • Biết hành động (action-taking): tự thực thi các bước (chạy lệnh bash, sửa file), không chỉ gợi ý.
  • Persistent context (nhớ trong phiên): nhớ thông tin qua nhiều turns trong cùng session.

2.1 Context window: bộ nhớ làm việc của một phiên

Context window là vùng chữ Claude “nhìn thấy” trong một phiên. Claude Code giữ toàn bộ hội thoại (câu hỏi, câu trả lời, kết quả tool) trong context window. Khi context đầy, dùng /compact để tóm tắt. Context window không persistent qua session: mỗi session mới bắt đầu từ đầu (trừ CLAUDE.md được load tự động).

2.2 Permissions: Claude xin phép trước khi động vào hệ thống

Permissions (quyền) là cơ chế để Claude Code hỏi bạn trước khi thực hiện các hành động ảnh hưởng tới system (edit file, chạy command). Bạn có thể approve từng lần hoặc approve cho cả session. Trong CI dùng --dangerously-skip-permissions với sandboxed environment. Sandboxed environment là môi trường cô lập, nơi lỡ có sai sót cũng không chạm tới máy hay dữ liệu thật.

Quyền chia theo mức rủi ro của việc Claude định làm:

Loại việcToolMặc địnhVí dụ
Chỉ đọcRead, Glob, GrepChạy luôn, không hỏiMở session.ts để đọc
Ảnh hưởng hệ thốngEdit, Write, BashHỏi bạn trướcSửa điều kiện hết hạn, chạy npm test, xoá thư mục build/

Khi Claude hỏi, bạn có ba lựa chọn: cho lần này, cho phép tiếp các việc cùng loại trong phiên, hoặc từ chối. Muốn đổi mức nền thì nhấn Shift+Tab để chuyển chế độ quyền. Muốn khai báo cố định việc nào luôn cho, luôn hỏi hay luôn cấm thì dùng luật allow, ask, deny trong settings (bài 13, mục 8).

Sai
  • “Claude Code nhớ mọi thứ từ hôm qua vì nó có context window.”
  • Tắt hỏi quyền trên máy làm việc thường cho nhanh.
  • Coi Claude Code là công cụ chỉ gợi ý code.
Đúng
  • Context window chỉ sống trong một session. Cái tự nạp lại ở session mới là CLAUDE.md.
  • Chỉ bỏ qua hỏi quyền trong môi trường cô lập như CI sandbox.
  • Claude Code là agent: đọc, sửa, chạy lệnh, commit.
Thực tế 11/2026 Theo How Claude Code works và Best practices:
  • Mỗi session mới bắt đầu với context window trống, đúng như đề thi. Ngoài CLAUDE.md còn có auto memory: Claude tự ghi lại những gì học được, và 200 dòng đầu (hoặc 25KB) của MEMORY.md được nạp ở đầu mỗi session.
  • Claude tự compact khi gần đầy. Bạn vẫn có thể chạy /compact kèm trọng tâm, ví dụ /compact focus on the API changes. Lệnh /context cho biết cái gì đang chiếm chỗ.
  • Phần lớn model hiện hành có cửa sổ 1 triệu token, nên hiếm khi hết chỗ. Tài liệu vẫn khuyên /clear giữa các việc không liên quan.
  • Nhấn Shift+Tab để xoay vòng các chế độ quyền: Auto, Manual, Accept edits, Plan. Từ Claude Code v2.1.283 trở lên, Auto là chế độ khởi động mặc định cho terminal và VS Code. Đề thi chỉ cần biết: Claude hỏi quyền trước hành động ảnh hưởng hệ thống.
Cốt lõi. Claude Code khác chatbot ở chỗ nó hành động. Vì vậy hai thứ quan trọng nhất là context (Claude đang biết gì) và permissions (Claude được làm gì).

3. How It Works

CCDV-F D3 CCAR-F D3 Nền

Hình dung đời thường
Một thợ sửa điện đến nhà bạn. Anh nghe bạn tả sự cố, chọn dụng cụ (bút thử điện, kìm), xin phép bạn trước khi cắt cầu dao, làm xong thì xem kết quả. Chưa sửa xong thì anh chọn dụng cụ khác. Khi hết lỗi, anh báo lại. Đó là một vòng lặp của agent.

Dưới hood, Claude Code chạy vòng lặp agent (agent loop):

  1. Nhận message của bạn
  2. Quyết định cần dùng tool nào (Bash, Read, Edit, Glob, Grep…)
  3. Thực thi tool (với permission check)
  4. Đưa kết quả tool vào context, lặp lại bước 2–4
  5. Trả lời cuối cùng khi đủ thông tin

Tools mà Claude Code có:

ToolLàm gìVí dụ trong đời thường
BashChạy shell commandsBấm nút “chạy thử” hoặc “cài thư viện”
ReadĐọc fileMở một tài liệu để đọc
WriteTạo file mớiTạo một tài liệu trắng
EditSửa fileSửa một đoạn trong tài liệu có sẵn
GlobTìm file theo patternTìm mọi file có đuôi .test.ts
GrepTìm nội dung trong fileDùng Ctrl+F trên cả thư mục
WebSearch, WebFetchTìm trên web, tải một trang webTra cứu tài liệu hướng dẫn

Ví dụ chạy từng vòng cho yêu cầu “test session.test.ts đang fail, hãy sửa”:

VòngClaude chọnQuyềnKết quả vào context
1Grep tìm SessionManagerĐọc, thường không cần hỏiDanh sách file chứa từ khoá
2Read file session.tsĐọc, thường không cần hỏiNội dung file
3Edit sửa điều kiện hết hạnHỏi bạn (sửa file)Báo đã sửa
4Bash chạy npm testHỏi bạn (chạy lệnh)Test pass
5Không gọi tool nữaKhôngTrả lời cuối: “Đã sửa, test pass”

Vì kết quả của mỗi vòng nằm lại trong context, việc đọc file rất lớn hay chạy lệnh in log dài làm context đầy nhanh. Khi cần dò nhiều file mà không muốn làm đầy phiên chính, giao việc dò cho một subagent (bài 13, mục 4).

Bẫy. Đọc file và tìm kiếm là việc “chỉ đọc”, còn sửa file và chạy lệnh mới “ảnh hưởng system”. Đề hay hỏi hành động nào cần xin quyền: câu trả lời đúng là nhóm sửa file và chạy command.
Thuật ngữ
Tool
Một khả năng Claude Code có thể dùng: đọc file, sửa file, chạy lệnh, tìm kiếm.
Pattern
Mẫu tên file, ví dụ *.ts là mọi file đuôi .ts.
Turn
Một lượt trao đổi: bạn nói, Claude đáp.
Permission check
Bước Claude Code dừng lại hỏi bạn trước khi làm việc có thể gây thay đổi.

4. The EPCC Workflow

CCAR-F D3 CCDV-F D3

Hình dung đời thường
Sửa nhà thì không ai cầm búa đập tường ngay. Thợ đi xem nhà trước (khảo sát), vẽ bản vẽ và báo giá (kế hoạch), rồi mới thi công (làm), cuối cùng nghiệm thu và ghi vào sổ (bàn giao). Bốn bước đó chính là EPCC.

EPCC là workflow tiêu chuẩn cho coding tasks. Tên viết tắt từ bốn giai đoạn:

Giai đoạnMô tảTip
ExploreHiểu codebase, context, requirements"Read the auth module and explain how sessions work"
PlanThiết kế approach trước khi codeNhấn Shift+Tab để vào plan mode
CodeViết code với vòng phản hồi ngắnYêu cầu tests cùng lúc với implementation
CommitGit commit với message rõ ràng"Commit with a conventional commit message"

4.1 Plan mode (Shift+Tab)

Plan mode là chế độ chỉ đọc. Khi bật, Claude sẽ chỉ đọc/phân tích, không thực thi hành động nào. Dùng để review kế hoạch trước khi approve. Trả lời "looks good, proceed" để bật lại action mode. Có thể cũng dùng /plan slash command.

Ví dụ trọn một lượt EPCC cho việc “thêm retry khi thanh toán lỗi”:

Ví dụ EPCC flow:

Explore:
> Read the payment module and understand the current flow

Plan (Shift+Tab on):
> I need to add retry logic for failed payments. Plan the implementation.
Claude: [đọc code, không viết gì]
"I'll add exponential backoff in PaymentService.process():
1. Wrap the API call in try/catch
2. Retry up to 3 times with 1s, 2s, 4s delays
3. Log each retry attempt
4. After 3 failures, emit PaymentFailed event"

Code (Shift+Tab off):
> Implement that plan

Commit:
> Commit the changes with a conventional commit message
  • Exponential backoff: chờ lâu dần giữa các lần thử lại (1 giây, 2 giây, 4 giây), để không dồn dập vào một dịch vụ đang lỗi.
  • try/catch: bọc đoạn code dễ lỗi để bắt lỗi thay vì để chương trình dừng.
  • Conventional commit: cách đặt message có khuôn, như feat: add payment retry.
Sai
  • Gõ “add OAuth login” rồi để Claude sửa ngay trong codebase lạ
  • Claude sửa nhầm module, bạn phải dọn lại
  • Tin rằng tăng effort giúp Claude đoán đúng chỗ cần sửa
Đúng
  • Explore: đọc code liên quan trước
  • Plan: thống nhất kế hoạch, rồi mới Code và Commit
  • Sai hướng thì phát hiện ở bước kế hoạch, không phải sau khi đã sửa file
Thực tế 11/2026 Theo tài liệu permission modes:
  • Shift+Tab xoay vòng các chế độ quyền. Khi plan mode bật, thanh trạng thái hiện plan mode on. Nhấn Shift+Tab tiếp để thoát khi không có hộp duyệt kế hoạch.
  • /plan đặt đầu một prompt để vào plan mode ngay, ví dụ /plan fix the auth bug. Với đề thi, “toggle” vẫn là đáp án gần nhất.
  • Khi kế hoạch xong, Claude hiện hộp lựa chọn: duyệt và dùng auto mode, duyệt và tự duyệt từng lần sửa, hoặc “No, keep planning”. Nhấn Ctrl+G để mở kế hoạch trong editor và sửa trực tiếp.
  • Đề thi nói “trả lời looks good, proceed”. Thực tế bạn chọn mục duyệt trong hộp trên. Cả hai đều có nghĩa là bạn cho phép Claude bắt đầu sửa file.
Bẫy. Plan mode không phải lúc nào cũng cần. Sửa một lỗi nhỏ có stack trace thì làm thẳng. Dùng plan mode cho việc nhiều file hoặc nhiều hướng làm (so sánh với bài 13, mục 4).

5. CLAUDE.md: bộ nhớ của project

CCAR-F D3 CCDV-F D3

Hình dung đời thường
Mỗi sáng nhân viên mới quên sạch mọi thứ của hôm qua. Bạn không dặn lại cả buổi sáng mà dán sẵn một tờ hướng dẫn ở cửa: “máy in ở tầng 2, lệnh chạy test là npm test, không sửa thư mục legacy”. Đến nơi, nhân viên đọc tờ này trước tiên. CLAUDE.md chính là tờ hướng dẫn đó.

CLAUDE.md là "memory" của Claude Code về project của bạn. Mỗi lần bắt đầu phiên, CLAUDE.md được nạp tự động, nên bạn không cần nhắc lại quy ước, lệnh hay bối cảnh mỗi lần. Mục này là phần nhập môn theo khoá Claude Code 101; thứ bậc các cấp CLAUDE.md, @import và /memory ở bài 13, mục 1.

5.1 Ví dụ: CLAUDE.md của một dự án Next.js

Cấu trúc CLAUDE.md ví dụ (Next.js project):

# Project: E-commerce Dashboard

## Stack
- Next.js 15 (App Router), TypeScript strict mode
- Prisma ORM + PostgreSQL
- Tailwind CSS + shadcn/ui
- Vitest for unit tests, Playwright for E2E

## Commands
- `npm run dev` — start dev server on :3000
- `npm run test` — run all Vitest tests
- `npm run test:e2e` — Playwright E2E (needs dev server running)
- `npm run db:migrate` — run pending Prisma migrations

## Conventions
- Components in `src/components/`, pages in `src/app/`
- Use server components by default; add "use client" only when needed
- All DB queries go through `src/lib/db.ts`, never import Prisma directly
- Error boundaries required for all route segments
- Vietnamese comments where logic is non-obvious

## Common Mistakes to Avoid
- Do NOT use `export default` for components — use named exports
- Do NOT call `prisma` directly — always go through `src/lib/db.ts`
- Run `npm run test` before committing
  • Stack: công nghệ dự án dùng. Claude khỏi phải đoán.
  • Commands: lệnh build, test, chạy thử. Claude gọi đúng lệnh thay vì thử bừa.
  • Conventions: quy ước đặt tên, đặt file, cách truy cập database.
  • Common Mistakes: những lỗi Claude hay mắc ở dự án này. Dùng “Do NOT” cho điều chắc chắn không được làm.

Tạo CLAUDE.md: Dùng /init để Claude tự phân tích codebase và tạo CLAUDE.md ban đầu. Sau đó cập nhật thủ công khi học được pattern mới.

5.2 CLAUDE.md theo thư mục

Subdirectory CLAUDE.md: Đặt CLAUDE.md trong src/api/ để chỉ áp dụng khi làm việc trong đó. Dùng cho context đặc biệt của từng module.

Sai
  • Nhắc lại stack và lệnh test ở đầu mỗi phiên
  • Nhét quy ước riêng của src/api/ vào CLAUDE.md gốc cho mọi module đọc
  • Tin rằng Claude nhớ hội thoại hôm qua
Đúng
  • Ghi stack, lệnh, quy ước vào CLAUDE.md một lần, /init để có bản đầu
  • Đặt CLAUDE.md riêng trong src/api/ cho phần chỉ áp dụng ở đó
  • Mọi điều cần nhớ lâu thì ghi vào CLAUDE.md
Thực tế 11/2026 Theo tài liệu memory (đã tóm tắt ở bài 13, mục 1): Claude Code còn nạp CLAUDE.md của mọi thư mục cha, có cấp ~/.claude/CLAUDE.md riêng cho bạn, và repo dùng AGENTS.md thì Claude đọc được file đó thay CLAUDE.md. Lệnh /init cũng là lệnh được tài liệu nhắc để tạo CLAUDE.md khởi đầu. Đề thi chỉ cần bạn nhớ ý: CLAUDE.md nạp tự động mỗi phiên, thư mục con nạp khi làm việc ở đó.
Bẫy. “Context window nhớ cả hôm qua.” Sai: mỗi session mới bắt đầu với CLAUDE.md cộng tin nhắn mới. /compact chỉ tóm tắt trong session hiện tại, không lưu qua session.
Thuật ngữ
Memory
Thông tin Claude Code mang theo từ phiên này sang phiên sau. Với đề thi, đó là CLAUDE.md.
Convention
Quy ước làm việc của đội: đặt tên, đặt thư mục, cách viết test.
Module
Một phần code có nhiệm vụ riêng, thường nằm trong một thư mục (ví dụ phần API).
/init
Lệnh để Claude tự quét codebase và viết bản CLAUDE.md đầu tiên.

6. Workflow Tips

CCAR-F D3 CCDV-F D3

Hình dung đời thường
Giao việc cho đồng nghiệp, câu “sửa cái form đi” khiến họ phải hỏi lại ba lần. Câu “thêm kiểm tra email ở form đăng ký, đừng làm hỏng test đang có” thì họ làm được ngay. Làm việc với Claude Code cũng vậy: yêu cầu càng cụ thể, càng ít vòng sửa lại.

6.1 Cách viết prompt hiệu quả

  • Cụ thể hơn mơ hồ: "Add input validation for email field in RegisterForm component" tốt hơn "fix the form"
  • Nêu ràng buộc: "without breaking the existing tests" / "matching the existing code style"
  • Đòi viết test: "implement X, write tests first" (TDD) hoặc "write tests for the code you just wrote"
  • Kiểm tra trước khi commit: "run the tests and check for TypeScript errors before committing"
  • Input validation: kiểm tra dữ liệu người dùng nhập vào có hợp lệ không (ví dụ email phải có dấu @).
  • TDD (test-driven development): viết test trước, rồi viết code cho tới khi test đạt.
Sai
  • “fix the form”
  • “add feature X” không nói gì về test hay phong cách code
  • Commit ngay khi Claude báo xong
Đúng
  • “Add input validation for email field in RegisterForm component”
  • Nêu ràng buộc: giữ test hiện có, theo phong cách code hiện có
  • Chạy test và kiểm tra lỗi TypeScript trước khi commit

6.2 Debugging với Claude Code

Debugging là tìm và sửa lỗi. Cách làm tốt: dán nguyên thông báo lỗi, nói rõ file nào cần đọc, và nói rõ điều không được đổi.

> This test is failing:
  FAIL src/auth/session.test.ts
  > SessionManager > should expire sessions after timeout

  Error: Expected 401, received 200

  Read the test and the SessionManager code, understand why this is
  failing, and fix it without changing the test expectations.
  • Dòng Expected 401, received 200 cho Claude biết kết quả mong đợi và kết quả thực tế khác nhau ở đâu.
  • “Read the test and the SessionManager code” bắt Claude Explore trước khi sửa.
  • “without changing the test expectations” chặn lối tắt là sửa test cho khớp code sai.

6.3 Slash commands hay dùng

Slash command là lệnh bắt đầu bằng dấu /, gõ ngay trong khung chat của Claude Code.

/compactTóm tắt lịch sử hội thoại, giải phóng context
/planBật, tắt plan mode (chỉ đọc, không hành động)
/rewindQuay về checkpoint trước
/configMở settings UI
/mcpQuản lý MCP servers
/permissionsXem và thay đổi quyền
Thực tế 11/2026 Theo tài liệu commands và best practices:
  • /rewind có alias /checkpoint và /undo. Nhấn Esc hai lần ở ô nhập trống cũng mở menu rewind, cho phép quay lại code, hội thoại hoặc cả hai. Checkpoint chỉ phủ file Claude sửa bằng tool sửa file của nó, không phủ thay đổi do lệnh Bash gây ra, và đi cùng git chứ không thay git.
  • /plan vào plan mode, có thể kèm mô tả việc. /memory mở các file CLAUDE.md và auto memory. /clear bắt đầu lại sạch giữa hai việc không liên quan.
  • Quy tắc “two strikes”: nếu đã sửa cùng một lỗi hai lần mà Claude vẫn sai, đừng sửa lần thứ ba. Chạy /clear và viết lại prompt, nêu cả điều bạn đã học được.

6.4 Integration với IDE

Claude Code có extension cho VS Code và JetBrains. Lợi ích: file navigation trực tiếp từ chat, diff view cho các thay đổi, error highlighting tích hợp. Mở extension bằng Ctrl+Shift+C (VS Code). Diff view là màn hình hiện các dòng sắp thêm (xanh) và xoá (đỏ), để bạn duyệt trước khi chấp nhận.

Thực tế 11/2026 Tài liệu VS Code extension không liệt kê phím Ctrl+Shift+C. Các phím được ghi là Cmd/Ctrl+Esc để chuyển focus giữa editor và Claude, Option/Alt+K để chèn tham chiếu tới file và đoạn đang chọn, và Command Palette (Cmd/Ctrl+Shift+P, gõ “Claude Code”). Phím của bài giảng gốc có thể đã đổi hoặc là bản ghi cũ. Bài này giữ nguyên để khớp tài liệu thi. Phím Ctrl+Shift+C chưa được kiểm chứng trên bản hiện hành, nên hãy mở Command Palette khi cần chắc chắn.

7. Lưu ý ôn thi

Hình dung đời thường
Ôn thi lái xe thì không học thuộc cả sách luật. Bạn nhớ vài biển báo hay gặp và vài tình huống hay hỏi. Mục này cũng vậy: chỉ gom những điều đề thi hay hỏi nhất về Claude Code.
CCAR-F D3 (20%): quy trình EPCC (Explore → Plan → Code → Commit), plan mode (Shift+Tab), thứ bậc CLAUDE.md và /init, quy tắc two-strikes, /compact khi context đầy, /rewind để hoàn tác.
CCDV-F D3 (3,1%): chỉ cần biết Claude Code là coding agent có context window, các tool chính (Bash, Read, Edit, Glob, Grep), và cách đưa nó vào quy trình làm việc của developer.
