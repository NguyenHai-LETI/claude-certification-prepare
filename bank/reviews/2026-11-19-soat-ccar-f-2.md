## Rủi ro còn lại
- **Subagent fork làm lung lay mệnh đề "subagent không thừa hưởng lịch sử".** Agent SDK hiện cho Claude gọi Agent tool với `subagent_type: "fork"` (từ Claude Code v2.1.302), và trong Claude Code tương tác fork mode bật mặc định. Exam guide v1.0 vẫn dạy "context phải truyền tường minh". Các câu có phương án/giải thích dựa trên mệnh đề tuyệt đối này (Z11, C232, L01 đã sửa; còn C228, Z13… ngoài lô) nên được rà để thêm "trừ fork" hoặc tránh phương án nhiễu mà fork làm thành đúng.
- **Z11 gần trùng C228 (cùng S3):** cùng quyết định "đưa phát hiện kèm metadata nguồn vào prompt của subagent tổng hợp". Z11 là câu tình huống, chọn một đáp án (đúng format đề thật); C228 là câu "Choose TWO" hỏi trực tiếp. C228 ngoài lô này, chưa có `reviewed`; đề nghị người soát C228 cân nhắc retire C228 và giữ Z11.
- **`tool_choice` `any`/`tool` (D08, các câu cùng chủ đề):** đề thi theo exam guide coi `any` là đáp án; thực tế 11/2026 nhiều model mới trả 400. Giải thích đã ghi rõ, nhưng phần này đổi nhanh, cần kiểm lại mỗi khi có model mới.
- **Tool Task → Agent:** Z10, C233 và giải thích dùng tên "Task" theo exam guide v1.0; docs SDK hiện gọi là `Agent` (vẫn hiện "Task" trong `system:init`). Ngoài ra subagent SDK mặc định chạy nền (`async_launched`), khác mô hình "gọi rồi chờ" mà đề ngầm định.
- **Mẫu lỗi lặp lại của bộ ccx (lô D1 S4–S6):** giải thích một câu chỉ nói đáp án đúng (19/30 câu); phương án nhiễu người rơm kiểu "kỹ sư tự làm tay", "chọn ngẫu nhiên", "nhờ đoán"; "giảm temperature" vẫn còn rải rác.

## Đề xuất sửa

### D02

**OLD**
```yaml
      - Lower the temperature so that the model chooses between the two similar tools more consistently.
      - Remove one of the two tools at random and see what breaks.
```
**NEW**
```yaml
      - Add a routing classifier in front of the model that picks one of the two tools before each request.
      - Add few-shot examples of the right tool choice to the system prompt, leaving both descriptions unchanged.
```

**OLD**
```yaml
    explanation: "Tool trùng nghĩa thì đổi tên, viết lại mô tả, hoặc tách thành các tool có hợp đồng vào/ra rõ ràng. Cũng rà system prompt: từ khoá trong prompt có thể kéo model về một tool."
```
**NEW**
```yaml
    explanation: "Hai tool có mô tả gần như trùng nhau thì gốc lỗi nằm ở chính tên và mô tả: đổi tên, viết lại mô tả nêu rõ mục đích, định dạng vào/ra và khi nào không dùng tool này, hoặc tách thành các tool có hợp đồng rõ. Đây là bước rẻ và đúng gốc nhất. Thêm routing classifier trước model là over-engineering cho một lỗi do mô tả kém. Few-shot trong system prompt chỉ vá triệu chứng, mô tả mơ hồ vẫn còn nguyên. Nhắc tên hai tool nhiều hơn trong system prompt còn có thể kéo model về một tool sai; nên rà system prompt để gỡ những từ khoá như vậy."
```
